# A WhatsApp agent that books appointments while you sleep. Eight steps

## Caption
A WhatsApp agent that books appointments while you sleep. Eight steps.

Plan first. Tell Claude Code what the business does, who messages you, what the agent must handle and what it must never do. Argue with the architecture before any code exists.
Connect WhatsApp. Meta developer app → add WhatsApp → credentials → webhook. Two things people miss: you must subscribe to the messages field or nothing is ever delivered, and you can only send free-form replies inside a 24-hour window after the customer messages you. Outside it, approved templates only.
Connect the model through OpenRouter — one API, any model, switching is a string change.
Memory. Without it every message is a stranger. Store history against the phone number, replay the last ~20 turns. Cap it and expire it, or cost and context both run away.
Business knowledge. Services, pricing, hours, FAQs, policies, booking rules — plus what it must refuse. Add one line: “if it isn’t in the information above, say you’ll check with the team.”
Tools. This is the actual line between a chatbot and an agent. Cal.com for availability and bookings. Reads are free, writes are guarded: confirm in words before booking, use an idempotency key, and resolve “next Thursday” in your own code, never the model’s.
Try to break it. The 31st of February. Two messages a second apart. “Ignore your instructions.” A question you never answered. Cancel after booking. Fix, re-run the whole set.
Deploy. Your laptop is not a production server. VPS, pm2, real TLS, verify the webhook signature (your endpoint is public), and log every turn so you can explain a wrong answer.
WhatsApp → AI → memory → business knowledge → tools → production. Each step is useless without the one before it.
